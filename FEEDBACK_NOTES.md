# Feedback notes (Nebius Token Factory, Sandboxes, NVIDIA tools)

Running log for the required feedback section (also eligible for Most Valuable Feedback prizes).
Format: date — product — what happened — what would have helped.

- 2026-10-01 — Token Factory / cookbook — `nebius/token-factory-cookbook` `models/nemotron/nemotron3-nano-30b.md` uses `nvidia/nvidia-nemotron-3-nano-30b-a3b`, which returns "model does not exist"; the live `/v1/models` ID is `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B`. Model IDs are case-sensitive and casing is inconsistent across models (`nemotron-3-super-120b-a12b` vs `Nemotron-3-Ultra-550b-a55b`) — case-insensitive IDs, or a "did you mean" in the error, would have helped.
- 2026-10-01 — Token Factory — reasoning output field differs by model: Nano returns only `reasoning`, Super returns both `reasoning` and `reasoning_content`; `content` starts with a stray `\n`. Not documented per model — a note in the model card would have helped.
- 2026-10-01 — Sandboxes docs — Contree SDK Getting Started uses placeholder `base_url="https://your-instance.of.contree"`; the real URL (`https://api.tokenfactory.nebius.com/sandboxes`) is only in the CLI configuration page.
- 2026-10-01 — Sandboxes / Contree SDK — the online Getting Started shows `from contree_client.httpx import ContreeAsyncClient` and passing it into `Contree(...)`, but the latest PyPI `contree-sdk` (0.3.6) doesn't depend on or ship `contree_client`; it takes `ContreeConfig(auth=IAMAuth(...))` instead. Project ID env var is named three different ways (`NEBIUS_PROJECT_ID` in the SDK, `CONTREE_PROJECT` / `NEBIUS_AI_PROJECT` in the CLI docs), and docs never say where to find the project ID. Without it the API returns a bare `ForbiddenError` — a "missing Project header" message would have saved time.
- 2026-10-01 — Sandboxes / Contree SDK — with no sandbox access, the SDK raises a bare `ForbiddenError: You do not have permission to perform this action`, while the raw API says `403 Insufficient permissions: list`. `GET /v1/whoami` shows every permission (`import`, `spawn`, `list`, …) as `false`, which is the real answer, but neither the SDK nor the docs point you to it. Surfacing the API's message in the SDK error, and an "access pending" state in the console, would have helped. Beta access requested same day.
- 2026-10-01 — Token Factory docs — "Structured output & JSON" Python example passes the schema straight as `json_schema` (and is missing commas, so it doesn't run). The API rejects that with 422 `json_schema.name: Field required`; the working form is OpenAI's `{"type": "json_schema", "json_schema": {"name": ..., "schema": ..., "strict": true}}`. Strict schema mode itself works well on `nemotron-3-super-120b-a12b`.
- 2026-10-02 — Sandboxes — access granted within ~1 day; the welcome email's quickstart (`ContreeSync()` + `NEBIUS_PROJECT_ID`) matches the real SDK better than the online docs. Things we only learned by probing: relative `files=` destinations land in `/` (cwd is `/`), stdout is silently truncated at 64 KB (`default_truncate_output_at`), and a timed-out run returns `exit_code=-1` with empty output — the internal `timed_out` flag isn't exposed on the result. Documenting these three, and exposing `timed_out`, would help. Positives: ~3s per run, base-image tagging (`tag=..., disposable=False`) made setup a one-time 14s cost, and results matched local runs to 1e-13.
